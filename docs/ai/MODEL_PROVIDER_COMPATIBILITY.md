## Harness contract and safe invocation

`runner.mjs` builds separate OpenRouter and Together Chat Completions bodies, requests a minimal Idea Card or nine-card slate with `response_format.type=json_schema`, and validates JSON, required fields, constraint IDs, obvious prohibited mechanisms and the canonical strategy set. These synthetic lexical constraint checks are only a screen; human review is required to establish semantic compliance and feasibility. The fixture contains no personal or confidential data. The harness rejects missing usage, model substitution, malformed output, truncation, refusal and ambiguous dispatched-request failures. It never automatically retries a potentially billable request.

For OpenRouter, the harness requests `provider.require_parameters:true`, `provider.only` for a named upstream and `allow_fallbacks:false`. It reads the authenticated [generation metadata endpoint](https://openrouter.ai/docs/api/api-reference/generations/get-generation) after a response, verifies `provider_name`, and records total cost and reasoning tokens when reported. A missing or mismatched upstream is not an accepted result. For Together, it verifies the returned model ID and usage. Provider claims of strict JSON Schema are still checked by server-side validation.

The free CLI first checks the current OpenRouter model and upstream catalogs for exact zero input and output prices and advertised schema support. For Together it requires the exact Ternary Bonsai ID in the authenticated account model list and a current official page displaying zero price. `paid-cli.mjs` is a separate local entry point with an explicit `--authorized-pilot` switch, a frozen synthetic fixture hash, two exact OpenRouter candidates, fresh catalog and account checks, atomic ledger reservation, and post-request billing reconciliation. It has no Together paid path. The ignored output folder holds synthetic responses and the SQLite ledger; CI runs mocks without credentials. Never commit or print keys.

## Mock coverage and missing live evidence

`pnpm test:model-bakeoff` checks distinct adapter request bodies, zero-price preflight, semantic rejection even with copied constraint IDs, accepted usage and routing, 400/401/402/429 classes, malformed JSON, refusal, truncation, missing or over-budget usage, uncertain POST outcome and upstream mismatch. All cases use in-process mock responses and consume no provider credit. A 5xx is classified by `classifyStatus`; live transient retry policy remains disabled. The compatibility gate still requires a successful free OpenRouter response with verified upstream and cost, stronger JSON Schema enforcement evidence, actual account debit comparison and rate-limit observations. These are pending.

OpenRouter charges can differ by upstream. Its public catalog rate is not a universal price promise, and default routing can silently change upstream. The owner approved the named candidates and $1 aggregate pilot ceiling; the local ledger and current-key usage comparison implement that boundary. Together's credit balance and deduction cannot yet be reconciled through a verified endpoint, so its paid candidates remain blocked. No hard-coded static price substitutes for observed debit.

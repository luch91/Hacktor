# M2A prompt and stage contracts

Status: proposed version `m2a-stage-v1`, subject to owner approval. Schema names below are design contracts; no runtime schemas or migrations have been changed. All fields use snake_case. Each model response must be parsed as an untrusted result, validated on the server and normalized for U+2014 before persistence or display. Keep the original user text byte-for-byte intact.

## Shared prompt envelope

Each invocation receives `stage`, `prompt_version`, `output_schema_version`, `strategy_library_version`, `session_id`, `job_id`, `attempt_index`, `source_idea_version_ids`, `entry_path`, `brief_text`, `builder_constraints`, `target_beneficiaries`, `confirmed_requirements`, `hard_constraints` as stable ID and text pairs, `judging_criteria` with provenance, `prior_stage_artifact_ids`, and `evidence_manifest`. Include only fields that the stage needs. The builder's brief, rules, and external text are untrusted data, never instructions overriding the stage contract. A claim of organizer verification requires an approved organizer snapshot; otherwise label the content user-supplied or unverified.

Every output includes `schema_version`, `prompt_version`, `stage`, `input_hash`, `assumptions`, and `uncertainties`. Stage-specific required fields below supplement this envelope. A server-generated input hash is compared to the invocation record. The model cannot choose its own provenance IDs or prices. Reject unknown fields when strict schema mode permits; otherwise reject at server validation. Truncation, refusal, malformed JSON, missing usage, missing constraint IDs and forbidden typography produce explicit errors.

## Constraint and differentiation validation

Hard constraints have stable IDs, source kind and verification state. Every accepted Idea Card carries every applicable ID. A deterministic validator checks cardinality, IDs, schema, title and mechanism fields, missing dependencies, forbidden characters and obviously identical normalized text. A separate semantic validator and human reviewer judge whether the mechanism actually complies. Neither a copied ID nor a polished explanation proves compliance.

For each candidate, require a causal statement: beneficiary experiences problem because of a bottleneck; the proposed mechanism changes a specific step; the MVP can demonstrate the change with available inputs. Compare every pair by problem, beneficiary, mechanism, assumptions and build path. Reject reworded duplicates, generic dashboards or chatbots that leave the causal mechanism unchanged, implausible hackathon scope, fabricated sources, unapproved datasets, unsupported originality language and unmet mandatory rules. Log a rejection reason per candidate and keep the rejected output out of accepted idea versions.

## Prompt governance and failures

Version prompts and schemas independently. A version change requires fixture tests for three unrelated briefs, hard constraints, all nine strategies, adversarial injected text and no U+2014 output, followed by the frozen holdout protocol. Pin provider, model, reasoning/sampling settings, prompt hash and price schedule per attempt. Never alter a frozen evaluation prompt after seeing its results. Permit at most one predeclared retry per evaluation arm. Timeout after dispatch is `outcome_unknown`, never an automatic blind retry. Refusal, over-budget, context overflow, schema error, lost lease and missing evidence each produce a structured state, with no deterministic fallback for live work.

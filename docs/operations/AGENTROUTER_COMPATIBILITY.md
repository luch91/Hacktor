# AgentRouter `.org` application compatibility decision

Status: **blocked for Hacktor backend inference** pending a documented and account-authorized generic application path. This does not hold OpenRouter or Together evaluation open.

The owner observed a direct PowerShell POST to `https://agentrouter.org/v1/chat/completions` with `gpt-5.6-sol` fail as `unauthorized_client_error`, `UNAUTHENTICATED`, `unauthorized client detected`. This is evidence of a client-access failure, not proof that the token is invalid or that promotional credits are spendable for an independent server application. No credential was available in this worktree and no additional inference request was made.

The [official `agentrouter-org/docs` repository](https://github.com/agentrouter-org/docs) documents Claude Code, Codex and other coding-client configurations. Its [Claude Code setup](https://github.com/agentrouter-org/docs/blob/main/en/start.md) uses `agentrouter.org` as an Anthropic base URL for that supported client. I found no official `.org` documentation granting ordinary HTTP, independent backend or Cloudflare Worker clients access to `/v1/chat/completions`, nor an alternative endpoint explicitly authorized for this account. An [issue in that documentation repository](https://github.com/agentrouter-org/docs/issues/21) independently reports `unauthorized client detected` for generic requests, with a supported coding client behaving differently; it is corroboration, not a service policy grant. Similarly named `agentrouter.to` developer API documentation belongs to a different domain and must not be assumed to apply to the owner's `.org` token.

Unknowns requiring a service or account answer: generic client eligibility; Worker/server application permission; token scopes; documented model IDs and quotas; whether the displayed $150 promotional balance applies to the endpoint and client type; structured output and retention terms; and any supported account-specific endpoint. Do not infer free credit use from a dashboard balance. Do not impersonate coding agents, forge client-identifying headers or bypass access controls.

If AgentRouter publishes an approved generic-client route and confirms this account's permissions, ask the owner to authorize **one synthetic connectivity request** with a numeric cap and the documented client contract. If it again returns `unauthorized_client_error`, retain the blocked classification and continue the main bake-off without it. No AgentRouter model is presently eligible for Hacktor's production ranking.
